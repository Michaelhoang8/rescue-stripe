        What recovery guarantees
        

          Any k distinct, consistent shards from the same set recover the file.
          Checksums reject accidental changes; a recovered payload hash and
          checks of additional shards validate the reconstruction. This
          implementation corrects known erasures, not unknown errors. Corrupt
          shards must be excluded rather than automatically repaired.
        

        

          Erasure coding is not encryption. Data shards reveal file bytes, and
          hashes are not signatures. Someone who can replace all metadata and
          checksums can create another internally consistent set. Store
          independent copies in independent failure domains; keeping every shard
          in one folder does not protect against losing that folder.
        

        

          Files are limited to 256 KiB. There are no uploads, persistence,
          accounts, or cloud storage. All coding runs in a local browser worker.
          Save shard files or bundles before closing the page. Original
          filenames are not embedded in shards.
